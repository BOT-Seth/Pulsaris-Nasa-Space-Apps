# Pulsaris

A self-assessment tool for astronauts on long missions. In about five seconds it shows your status, why, and the one thing to do next. It keeps missing data and uncertainty visible instead of guessing.

Built for the 2026 NASA Space Apps Challenge, **Create Health Monitoring Software for Astronauts on Space Missions**.

> Educational prototype. Not a medical device. Not clinically validated. Not tested with astronauts.

## Run it

```bash
npm install
npm run dev        # development server
npm test           # 17 unit tests for the scoring and the health rules
npm run build      # typecheck, build, and write dist/pulsaris.html
```

`dist/pulsaris.html` is one self-contained file. It opens from disk with no server and no network, fonts included.

Node 20 or newer.

## What it does

| Workflow | What happens |
|---|---|
| Today | One status, its cause, one action, and up to three pieces of evidence. All nine indicators sit below as a grid. |
| Daily check-in | Mood, sleepiness (Karolinska scale), confirm last night's sleep. Answers are kept as a draft if you are interrupted. |
| Alertness check | A real 3-minute reaction test (PVT-B), scored against the NASA ISS pre-flight reference. Offered only when a sign of fatigue appears, or before a critical task. |
| Next step and follow-up | A sourced countermeasure step, a recorded action, and a scheduled re-check. Recording an action never clears a concern; only a re-check does. |
| Measurements | Each indicator: 8-day trend, your own baseline band, the rule and where its threshold comes from, why it matters in space, sources. |
| Body map | Measurements grouped by body system, with what that system does and how spaceflight affects it. Also where you report a symptom. |
| Plan and log | What is due, a timestamped record of everything entered, sharing state, JSON export. |

The six indicators the challenge names are all here: blood pressure, heart rate, blood sugar, body temperature, sleep hours, mood. Pulsaris adds heart rate variability, sleepiness and the alertness check.

## What the data is

Every reading carries a `provenance` field, and the interface shows it as a tag on every value.

| Tag | Meaning |
|---|---|
| Recorded | Last night's sleep duration, HRV and heart rate, computed from the MMASH dataset. Real people, 24 hours each, **on Earth. Not astronauts.** |
| Synthetic | Earlier nights and earlier entries, generated by a seeded script so that baselines and trends exist. Never shown without the tag. |
| Self-reported | What you tap or type: mood, sleepiness, blood pressure, blood sugar, temperature, symptoms. |
| Measured here | Reaction times from the alertness check on this device. |

There is no live sensor connection, by design.

## How NASA resources are used

- The alertness score uses the formula and the pre-flight astronaut reference (N = 24, speed 5.25, SD 0.24) from Dev et al. 2024, a NASA Human Research Program Standard Measures study.
- NASA HRP's hazard and risk pages are the basis for each "Why it matters in space" text and for the countermeasure wording.
- Heart rate, HRV and blood pressure are compared only with in-flight nights, never pre-flight, because all three fall in microgravity (Fritsch-Yelle et al. 1996, NASA JSC).

Full references are in the app under **Sources**, and in `src/domain/content.ts`.

## Limits you should know

- Thresholds marked "team starting point" are first values chosen from the cited literature. They are not validated.
- The alertness check is a browser implementation. Display and touch latency are not benchmarked, so the comparison with the reference is indicative.
- "Flag for crew medical officer" is a local state. Nothing is sent anywhere.
- The mission history is synthetic. A real mission would build the baseline from seven in-flight nights.
- Designed for an unsuited crew member at a cabin tablet. Not for gloves or suit displays.

## Where things are

| Path | Contents |
|---|---|
| `src/domain/` | Data model, health rules, alertness scoring, scenario builder, explanations and citations. Pure TypeScript, no UI. |
| `src/domain/domain.test.ts` | Unit tests. |
| `src/state/store.tsx` | App state, saved in the browser's local storage. |
| `src/ui/`, `src/views/` | Components and screens. |
| `src/styles.css` | The visual system. |
| `scripts/prepare-mmash.mjs` | Turns the MMASH dataset into `src/data/mmash.json`. States the beat-cleaning method. |
| `docs/` | Design system and scope documents. |

To regenerate the data: download [MMASH v1.0.0](https://physionet.org/content/mmash/1.0.0/), unpack it, and run `node scripts/prepare-mmash.mjs <path>/DataPaper`.

## Use of Super Intelligence (SI)

NASA Space Apps permits Super Intelligence (SI) tools and asks that their use be disclosed. This project used them as follows:

- **Code and interface text:** written with SI assistance, Anthropic Claude (Claude Code) and OpenAI Codex. The team chose the indicators, rules, thresholds and sources and reviewed the code; 17 automated tests cover the scoring and rules.
- **3D body figure (image):** SI-generated. A local FLUX.2 Klein reference image, a TRELLIS 2 mesh, then Blender finishing and targeted corrections (`src/data/body-model.json`, `source` field). The app shows a visible "SI-generated figure" mark on it and a caption under it. It is a navigation aid, not validated anatomy. The flat 2D fallback figure is hand-coded SVG.
- **Data:** the earlier nights and entries are generated by a seeded script (written with SI assistance) and are tagged "synthetic" on screen. Last night's sleep, heart rate and HRV are real MMASH recordings (Earth volunteers, not astronauts).
- **Pitch deck and demo video:** drafted with SI assistance and reviewed by the team; each says so on screen.
- **Not SI:** every health flag comes from explicit, deterministic rules in `src/domain/rules.ts`. No model makes a health decision at run time.
